# CLAUDE.md

Черновик игры для геймджема (2D top-down, космос, полёт на отдаче пушки).
Полный план и описание игры: Assets/Filip/GAME_PLAN.md.

## Техника
- Проект сохранён в Unity 6000.0.79f1, у пользователя стоит 6000.0.85f2:
  C:\Program Files\Unity\Hub\Editor\6000.0.85f2\Editor\Unity.exe
- Проект на URP 2D. В сцене-шаблоне уже есть Main Camera (тег MainCamera)
  и Global Light 2D. Спрайтам оставляй материал по умолчанию. При запуске
  проверь, что Global Light 2D есть в сцене; если нет, создай его из кода.
  Shader.Find не используй: в сборке шейдер может быть вырезан.
- Unity 6 API: у Rigidbody2D linearVelocity и linearDamping.
- Глобальная гравитация в настройках -9.81, её не меняй.
  У всех наших тел gravityScale = 0.
- Ввод: UnityEngine.Input (в проекте включены оба способа).
- Не создавай теги, слои и sorting layers: они хранятся в ProjectSettings,
  которые мы не коммитим. Порядок отрисовки задавай через sortingOrder.
  Столкновение пули с игроком отключай через Physics2D.IgnoreCollision.
- Интерфейс: uGUI из кода, UnityEngine.UI.Text со встроенным шрифтом
  LegacyRuntime.ttf. TextMeshPro не используй: он требует ручного импорта.
  Экраны и меню управляются клавишами, без кнопок мыши.
- Рестарт и смена уровня: без перезагрузки сцены. Удаляй объекты уровня
  и собирай их заново кодом. Статические поля сбрасывай при старте.
- Ошибки компиляции смотри в логе редактора:
  %LOCALAPPDATA%\Unity\Editor\Editor.log
  Если редактор закрыт, можешь проверить компиляцию запуском Unity
  в batchmode с -quit и -logFile.

## Архитектура
- Ветка filip/editor-objects: игра НЕ строится из кода при запуске. Всё лежит
  в сцене и префабах, ссылки назначены в Inspector ([SerializeField]).
  - Assets/Filip/DraftScene.unity: камера (CameraRig), Global Light 2D, HUD,
    объект DraftGame (список префабов уровней, стартовый уровень).
  - Assets/Filip/Prefabs/: Player, Bullet, Asteroid_*, Meteor_*, Ship,
    OxygenTank, OxygenCrystal, Background. Уровни: Prefabs/Levels/LevelN.prefab
    (корень с компонентом Level: имя, кислород, границы; HintMarker для подсказок;
    MeteorSpawner на корне включает метеоры).
  - Во время игры создаются только Instantiate префабов (уровень, пули,
    кристаллы, осколки, метеоры). Рестарт: Destroy уровня и новый Instantiate.
  - Меню Filip > Rebuild Prefabs And Scene (Editor/DraftSetup.cs) один раз
    делает все префабы из кода и levelN.txt. Повторный запуск ПЕРЕЗАПИСЫВАЕТ
    префабы и HUD/DraftGame в сцене. Art, SpriteFactory, LevelData теперь только
    для редактора. Простые формы лежат в Assets/Filip/Art/Shapes.
- Скрипты: Assets/Filip/Scripts/. Скрипты редактора: Assets/Filip/Editor/.
- Картинки: Assets/Resources/Art/. Уровни: Assets/Resources/Levels/.
  Звук: Assets/Resources/Audio/.
- Все числа баланса в одном классе Tuning константами в начале файла.
- Масштаб: 1 единица = 100 пикселей. Камера ортографическая, size 10
  (видно примерно 35.5x20 единиц). Клетка уровня 2x2 единицы.
- Вид игры: светится только важное для игры (игрок, пули, баллоны, метеоры).
  Камни крупные (2, 4, 6 единиц = 1, 2, 3 клетки), тёплые и светлые. Фон
  приглушён и не мерцает, чтобы не спорить с камнями.

## Правила Git
- Никогда не коммить в main. Вся работа в ветке filip/draft.
- git push не делай никогда, пока пользователь не напишет "заливай".
  Заливается только то, что уже работает, и пользователь сам говорит когда.
- После каждого шага делай только локальный коммит в ветке filip/draft.
- Если шаг что-то сломал и пользователь пишет "откати", вернись к предыдущему коммиту.
- Наша зона: только Assets/Filip/ и Assets/Resources/.
  Единственное исключение: файл CLAUDE.md в корне проекта.
- Не изменяй и не удаляй чужое: Assets/PlayerMovementScript.cs,
  Assets/GunScript.cs, Assets/Scenes/SampleScene.unity.
- Не коммить изменения в ProjectSettings/ и Packages/, даже если Unity
  изменил их сам. Перед каждым коммитом проверяй git status и добавляй
  только файлы из нашей зоны.
- Коммить файлы вместе с .meta. Если .meta ещё нет (Unity не открывался),
  закоммить без них и добавь их следующим коммитом.
- В main не сливай без "ок, сливай" от пользователя. При конфликте остановись.

## Правила работы
- Один шаг за раз. После шага остановись и жди отзыва.
- Не добавляй ничего сверх шага, даже если кажется полезным.
- Отчёт после шага: что сделано (3 строки), что нажать в Unity (3 строки).
- Когда пользователь пишет "слабо", "сильно", "медленно", меняй числа в Tuning.
- Пользователь не программист: в Unity он только открывает сцену и жмёт Play.
  Не задавай вопросов, решай сам и коротко пиши, что решил. Исключение:
  если git попросит имя и почту для коммита, спроси.
